# Destructuring

Imagine que você precisa 'desmontar' um objeto e armazenar cada attribute / propriedade em uma variable diferente.

Da maneira tradicional, faríamos assim:

```kotlin
class Person(
    val name: String?,
    val age: Int?,
    val pokemon: String
)


fun main(args: Array<String>) {

    val p1 = Person(
        "ash",
        22,
        "pikachu"
    );

    //'desmontando' esse objeto
    val nameInsano = p1.name;
    val ageInsano = p1.age;
    val pokemonInsano = p1.pokemon;
}
```

<br>

Conseguimos reduzir isso utilizando **destructuring**:

```kotlin
data class Person(
    val name: String?,
    val age: Int?,
    val pokemon: String
)

//pegando os attributes desse objeto
val (nomeInsano, ageInsano, pokemonInsano) = p1;
```

:warning: Você só consegue desmontar o objeto se a Classe desse objeto for uma `data` Class.


---

## Entendendo por debaixo dos panos

O `data` class gera automaticamente os métodos component1(), component2(), component3() etc — um pra cada property, na ordem que foram declaradas no constructor primário.

Quando você escreve:

```kotlin
val (nomeInsano, ageInsano, pokemonInsano) = p1;
```

O Kotlin por baixo dos panos chama:

```kotlin
val nomeInsano2 = p1.component1();
val ageInsano2 = p1.component2();
val pokemonInsano2 = p1.component3();
```


:book: A ordem das propriedades importa. Não tem como alterar.
