# Singleton Object

É uma classe que só pode ter 1 instancia / objeto.

Imagine que um projeto tenha algumas configurações:

- URL da API
- Ambiente


Queremos que exista apenas **um único objeto de configuração** em toda a aplicação.

Não queremos ficar fazendo isso:

```kotlin
val config1 = Configuracao() // objeto 1
val config2 = Configuracao() // objeto 2
val config3 = Configuracao() // objeto 3
```

É para esse tipo de situação que podemos utilizar um **Singleton Object**.

> :book: Singleton significa que teremos apenas **uma única instância / objeto** daquela Classe em toda a aplicação.

---
<br>

## Diferenca entre Anonymous Class e Singleton Object

- **Anonymous Class** → É usada quando precisamos implementar uma Interface ou herdar uma Classe abstrata de forma rápida, sem precisar criar uma Classe separada.

- **Singleton Object** → Usamos quando queremos que exista apenas **um único objeto / instância** daquela Classe na aplicação toda.

---
<br>


## Syntax

Estamos criando a Classe e ao mesmo tempo instanciando

```kotlin
// como se fosse uma class qualquer
object Configuracao {

    var urlApi: String = "http://api.com"
    var ambiente: String = "prod";


    fun ligarAmbiente(): Unit {
        println("ambiente funcionando");
    }

}
```

> :book: Em um Singleton Object, não declaramos um constructor como fazemos em uma Classe normal. O próprio Kotlin cria sua única instância, e nós apenas utilizamos esse mesmo objeto durante a aplicação.
>
> Se pudéssemos instanciar essa Classe utilizando `Configuracao()`, poderíamos criar vários objetos dela, o que iria contra a ideia de um Singleton.

<br>

Usamos esse objeto

```kotlin
fun main(args: Array<String>) {

    Configuracao.urlApi;
    Configuracao.ambiente;

}

```

---
<br>

## Resumindo

Viu um `object` Singleton no projeto, saiba que ele representa uma **Classe com uma única instância / objeto** em toda a aplicação.
