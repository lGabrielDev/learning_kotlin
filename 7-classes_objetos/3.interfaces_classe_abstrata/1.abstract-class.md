# Abstract Class

Usamos quando queremos uma classe base / pai, compartilhando atributos entre as classes filhas.

Abstract Class é uma classe parecida com uma interface. A principal diferença é que, por ser uma classe, ela também pode possuir atributos, além de métodos.

Por ser uma Classe `Abstract` ela não pode ser instanciada. Geralmente usamos ela como classe Pai.

Exemplificando fica mais fácil entender.

<hr>

## Criando uma Abstract Class

Imagine uma classe pai `Conta` com duas classes filhas: `ContaCorrente` e `ContaSalario`. No banco, todos os tipos de conta compartilham os mesmos attributes (como número, agência e saldo) e alguns methods (como `depositar()` e `sacar()`). 

Para evitar repetição de código e garantir que ninguém instancie uma `Conta` genérica, usamos uma classe abstrata como base.

1. Criamos a Classe Pai `Conta`:

    ```kotlin
    abstract class Conta (
        val numero: String,
        val agencia: String,
        var saldo: Double
    ){
    
        // methods com corpo
        open fun depositar(valor: Double): Unit{
            this.saldo += valor;
        }
    
        // methods sem corpo
        abstract fun sacar(valor: Double): Unit;
    }
    ```
   
    > :book: Uma Abstract Class já possui o `open` por padrão. Ou seja, pode ser herdada por outras classes.

<br>

2. Criamos as classes filhas `ContaCorrente` e `ContaSalario`:

    ```kotlin
   //Conta 1
    class ContaCorrente(
        numero: String,
        agencia: String,
        saldo: Double
    ): Conta(numero, agencia, saldo)
    {
        //methods abstratos que precisam ter o corpo definido
        override fun sacar(valor: Double) {
            println("saque feito com sucesso! - Conta Corrente");
        }
    }
    
   //Conta 2
    class ContaSalario(
        numero: String,
        agencia: String,
        saldo: Double
    ): Conta(numero, agencia, saldo)
    {
        //methods abstratos que precisam ter o corpo definido
        override fun sacar(valor: Double) {
            println("saque feito com sucesso! - Conta Salário");
        }
    }
    ```
   
:book: Quando você cria um objeto da classe filha, o construtor da classe pai também precisa ser chamado para inicializar a parte que veio dela.

## Inteface x Abstract Class

### Interface

- Não pode instanciar objetos (É uma interface, não é uma Class).
- Pode ter methods com e sem corpo (abstratos).
- Não trabalha com attributes
- Uma Classe pode implementar várias interfaces.

<br>

### Abstract Class

Usamos quando queremos uma classe base / pai, compartilhando atributos entre as classes filhas.

- Não pode instanciar objetos (Apesar de ser uma Class, ela é abstract).
- Pode ter methods com e sem corpo (abstratos).
- Pode ter attributes
- Uma Classe só pode herdar 1 única vez / 1 única classe.

<br>

### Resumindo

- Queremos apenas trabalhar com methods? -> `Intefaces`
- Queremos trabalhar com methods E attributes? -> `Abstract Class`
